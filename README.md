# 🔍 客服回复幻觉检测工具

[![Python](https://img.shields.io/badge/Python-3.11+-blue.svg)](https://www.python.org/)
[![Streamlit](https://img.shields.io/badge/Streamlit-1.60+-red.svg)](https://streamlit.io/)
[![License](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)

自动检测客服系统回复中的"幻觉"（Hallucination）—— 即回复内容与知识库不一致的情况。基于规则引擎与大模型双模式，支持 5 类幻觉分类、严重程度评估，并与人工标注进行对比验证。

## 📸 界面预览

启动后通过浏览器访问 `http://localhost:8501`，包含 4 个功能页：

- **检测结果** — 20 条回复的逐条检测表格，支持展开查看详情
- **对比分析** — 混淆矩阵热力图、幻觉类型饼图、严重程度柱状图
- **误判分析** — 误报/漏检详情、类型混淆矩阵、易错 Case 总结
- **分类体系** — 5 类幻觉的完整定义、示例和严重程度分级

## 🧠 幻觉分类体系

本工具定义了 **5 类幻觉**，按严重程度分 4 级：

| 类型 | 英文 | 定义 | 严重程度 |
|------|------|------|:--------:|
| **事实编造** | Fabrication | 知识库中完全不存在对应信息，凭空杜撰 | 🔴 高 |
| **数值歪曲** | Distortion | 知识库有对应信息但数值/参数被篡改 | 🔴 高 |
| **能力越界** | Overclaim | 系统假装执行了不具备的操作能力 | 🔴 高 |
| **安全误导** | Safety | 忽略或歪曲安全/健康风险信息 | 🔴🔴 严重 |
| **信息遗漏** | Omission | 知识库有关键限定信息但回复未提及 | 🟡 低 |

### 严重程度分级

| 级别 | 说明 | 典型后果 |
|------|------|---------|
| **严重** | 涉及人身安全/健康 | 孕妇使用禁忌成分、药物过敏风险 |
| **高** | 直接误导消费决策 | 材质造假、价格编造、虚假承诺 |
| **中** | 部分误导但后果可控 | 部分信息正确但关键细节错误 |
| **低** | 信息不完整，影响较小 | 遗漏统计信息、未提使用注意事项 |

## 🔬 检测方法

### Mock 规则引擎（默认，无需联网）

基于正则表达式和关键词匹配，实现 6 组检测规则：

| 规则 | 策略 | 覆盖 Case |
|------|------|-----------|
| 能力越界检测 | KB 含"未接入/不具备/需人工" + 回复含动作词（"已帮您"等） | h03, h10, h14, h18 |
| 限制绕过检测 | KB 要求特定渠道（短信等） + 回复直接给出信息 | h07 |
| 事实编造检测 | KB 明确否定 vs 回复肯定 | h04, h09, h11, h15, h19 |
| 数值歪曲检测 | 提取数值/材质/参数 → KB vs Reply 对比 | h01, h02, h05, h06, h08, h17 |
| 安全误导检测 | KB 含安全警告 + 回复忽略警告 | h13 |
| 信息遗漏检测 | KB 含量化限定 + 回复绝对化表述 | h20 |

### LLM API 引擎

调用 OpenAI 兼容 API，通过结构化 Prompt 让大模型逐条判断。每条的 Prompt 包含：
- 系统角色设定（幻觉检测专家）
- 5 类幻觉的完整定义与示例
- 输入数据：用户问题 + 系统回复 + 知识库
- 结构化 JSON 输出约束

支持 OpenAI、DeepSeek、通义千问、Moonshot 等兼容接口。

## ⚠️ 误判分析

当前 Mock 引擎在 20 条测试集上无误判，但以下类型在实际应用中容易出错：

1. **信息遗漏边界模糊** — "未提及"和"表述角度不同"难以自动区分，规则引擎可能误报
2. **部分正确部分错误** — 如 h04（电子发票正确但纸质发票错误），检测器需同时识别正误
3. **隐晦数值偏差** — 语义相近的数值（"2-3天" vs "3-5天"），纯规则方法难以精确区分
4. **上下文依赖的安全风险** — 如成分表中视黄醇等专业术语，需领域知识才能判断安全性

## 🚀 快速开始

### 环境要求

- Python 3.11+
- （可选）OpenAI 兼容 API Key

### 安装

```bash
git clone <repo-url>
cd illusion_setection
pip install -r requirements.txt
```

### 启动

```bash
# Mock 模式（默认，无需 API Key）
streamlit run app.py

# 或使用虚拟环境
.venv\Scripts\python.exe -m streamlit run app.py
```

### 配置 LLM 模式

在应用侧边栏选择 "LLM API 调用" 模式，填入 API Key 即可。支持三种配置方式：

1. **界面直接输入** — 侧边栏填写 API Key / Base URL / Model
2. **secrets.toml 持久化** — 复制 `.streamlit/secrets.toml.example` 为 `secrets.toml` 并填入配置
3. **环境变量** — 设置 `OPENAI_API_KEY` / `OPENAI_BASE_URL`

内置 DeepSeek、通义千问、Moonshot 快捷预设，一键填入 Base URL。

### 命令行验证

```bash
python verify.py
```

输出示例：

```
TP=18, TN=2, FP=0, FN=0
精确率: 100.00%  召回率: 100.00%  F1: 100.00%
```
